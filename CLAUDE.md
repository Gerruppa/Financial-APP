Layout (`src/financial_app/`, see ADR-0001):
- `domain/`: pure-Python calculations. It must never import NiceGUI, SQLAlchemy, Alembic or pywebview; `tests/test_architecture.py` enforces this. `domain/formatting.py` is the single Polish number and date formatter (`format_pln`, `format_percent`, `format_quantity`, `format_unit_price`, `format_date`, `format_datetime`, `format_count` (Polish plurals), `format_exact` for edit fields and `format_exact_percent` for a stored percent like a TER) and parser of typed input (`parse_number`, `parse_date`); use it for every amount or date shown in or read from the UI.
- `persistence/`: SQLite through SQLAlchemy. `models.py` holds the ORM models, `migrations/` holds Alembic revisions, and `db.init_db(path)` applies them at start-up, right after `backup.backup_database` copies the file into `paths.backups_dir()` (newest 30 kept). The database lives in the user's app-data folder (`paths.data_dir()`, overridable with `FINANCIAL_APP_DATA_DIR`), never in the repo. Change the schema only through a new migration: `.venv/Scripts/python.exe -m alembic revision --autogenerate -m "..."`. `tests/test_database.py` fails if the models and migrations drift apart.
- `domain/accounts.py`: Account Types (Bonds and Other, #64, are stored as text, so new types need no migration), the Tax Regime registry (`tax_regime_for`; OKI is a placeholder, Other only describes the 6-month rule for selling things) and `AccountDraft`, which validates Account fields and raises `AccountError` with a Polish message. `persistence/accounts.py` saves Accounts (`list_accounts`, `add_account`, `update_account`) and enforces case-insensitive unique names.
- `domain/spreadsheet_import.py`: reads the Transakcje sheet's columns, classifies tickers (`EXCH:SYM`, bonds `TYP-DDMMRR` → Bond Series, `Gotówka`, `Waluty_<CUR>`), builds the Transaction for each row (Actual Amount = the sheet's "Total PLN") and fingerprints rows so a re-import skips them.
- `sources/spreadsheet.py`: opens the workbook (openpyxl), `preview_import` (matches Konta and Instruments, the user's `Decisions` resolve the rest, nothing saved) and `save_import` (creates the new Instruments and saves every row or none). `ui/import_sheet.py` is its section in Ustawienia; an unmatched Konto can create an Account through `ui/accounts.py` `open_account_dialog` (#63), prefilled by `cash_currencies_of`. Transactions keep their Origin (`domain/transactions.py` `Origin`, migration 0011 adds `origin` and `external_id`).
- `domain/transactions.py`: Transaction Types (Deposit, Withdrawal, Buy, Sell, Dividend, Cost, Currency Exchange, DRIP, Split, Cash Transfer, Security Transfer so far), `TransactionDraft` validation, `buy_or_sell(...)` (builds a Buy/Sell and derives its Actual Amount; a foreign-currency one carries the user's optional `fx_rate` and the `NbpRate`, from which the `tax_amount` property follows, or a `BrokerConversion` (the PLN the broker charged and the Account's FX Conversion Fee %): the trade stores the percent, and its `fx_conversion_fee` and `effective_fx_rate` follow, the fee counting as a cost in the Tax Amount; `cash_currency` says whether it is paid from PLN or from foreign cash of the Instrument's currency, the commission always in PLN), `currency_exchange(...)` (PLN to a foreign Cash Currency or back, `to_pln`), `dividend(...)` (gross and withholding tax in the Instrument's or the chosen currency, the net amount into PLN at the user's rate or the NBP Rate, or the PLN the broker credited with a `BrokerConversion` (its fee a cost), or into foreign cash of that currency; no Instrument means interest), `cost(...)` (PLN, or from foreign cash valued at the NBP Rate), `drip(...)` (a Dividend reinvested into `quantity` units: a Lot costing the net amount, at the NBP Rate if foreign, no cash moving), `split(...)` (a `SplitRatio` X:Y, no amount), `cash_transfer(...)` (PLN to `target_account_id`, which `cash_balances` credits) and `security_transfer(...)` (units to `target_account_id`, no amount), `costs_by_account` (Costs, commissions and FX Conversion Fees) and `dividends_by_account`, `covering_exchange(buy)` (the "wymień walutę automatycznie" Exchange buying exactly the Buy's foreign amount), `cash_balances` (per Account, in any currency) and `lowest_cash_balance` (drives the insufficient-cash warning, per currency). `persistence/transactions.py` saves them (`add_transaction`, `add_transactions` (several at once, all or none), `update_transaction` and `delete_transaction`, each replaying the touched Positions to block a change that would leave a Sell or Security Transfer uncovered or a Split before the first Buy; `list_transactions`, newest first).
- `domain/lots.py`: the single FIFO engine (ADR-0003). `open_positions(transactions)` takes Transactions in entry order, sorts by date and the same-day order, and returns `Position`s (open `Lot`s with Actual `cost` and `tax_cost`, average price, value and result at a PLN price); a Split rescales open Lots (units × X/Y, costs kept) and a Security Transfer moves the oldest Lots to the target Account with their dates and costs; an uncovered Sell or Security Transfer raises `InsufficientQuantityError`, a Split before the Account held the Instrument `SplitBeforeFirstBuyError`. Same-day order: Split, Buy, Security Transfer, Sell, DRIP. `foreign_cash(transactions)` holds foreign cash as Lots per Account and currency (`ForeignCash`, with the realised FX result; spending more than held only warns and leaves a negative Lot), and `fx_result` sums an Account's realised and unrealised FX result.
- `domain/valuation.py`: `instrument_price(instrument, quote, rate_for)` decides the price a Position is valued at and its `PriceStatus`: the Manual Price while it is set (carrying the newest Quote to show beside it), else the newest Quote, else no price; no NBP Rate to convert it is its own status, and the rate is asked for only when there is a price. Its `Badge` (ręczna, nieaktualna when `stale`, bez źródła, do etapu 3 for `prices.STAGE_3_CLASSES`) shows beside the Position. A physical metal (`InstrumentDraft.metal_grams`, the metal weight of one unit, and `buyback_spread_percent`, migration 0015) has its prices (Manual Price and Quotes) as the spot of a troy ounce (`GRAMS_PER_TROY_OUNCE`): `unit_price` scales it to the unit less the spread (`unit_spot` without it), and `InstrumentPrice.spot` and `unit_spot_pln` keep the spot to show beside it. The Portfolio only displays it.
- `domain/prices.py`: `Quote`, `PriceSourceError` (Polish message), the Price Source keys (`YAHOO`, `BOSSA`, ...) and `SOURCE_NAMES`, and `sources_to_try(fallback_order, source_symbols)`: the Asset Class's Fallback Order, keeping only the sources the Instrument has a Source Symbol for (`symbol_in`: bankier.pl falls back to the Fund Code, the analizy.pl Source Symbol, #58; `without_fund_code_copy` drops a bankier.pl symbol equal to it, applied when the dialog opens and saves). Each Asset Class stores its own order (#41, `AssetClass.fallback_order`, copied onto `Instrument.fallback_order`; column `asset_classes.fallback_order`, comma-separated keys, migration 0018): `default_fallback_order(name)` gives the spec 4.1 defaults (any other class gets that of "Inne"), `validate_fallback_order` allows each of `FALLBACK_SOURCES` once (`FallbackOrderError`), `persistence/instruments.py` `set_fallback_order` saves it, `add_asset_class` gives a new class the current order of "Inne" (`new_class_fallback_order`) unless given one, and `clear_portfolio` restores the defaults. Ustawienia > Klasy aktywów shows each order and edits it in the class dialog (move, remove, add a source); `AssetClassesSection.on_changed` redraws the Instruments and the unpriced list. Instruments carry `source_symbols` (source key to symbol) in `InstrumentDraft`, saved in `source_symbols` (migration 0012).

The app re-implements the inwestomat.eu "Portfolio tracker" Google Sheet. The agreed spec is `docs/spec.md`, the glossary is `CONTEXT.md` (its Polish-to-English index is `GLOSSARY.md`, kept in step by `tests/test_glossary.py`) and key decisions are in `docs/adr/`. `reference/` holds the user's spreadsheet export and its Apps Script source; it is git-ignored because it contains personal financial data, so never commit it or copy its data into tracked files.

## Environment

- Python 3.14 in a virtualenv at `.venv/`. Dependencies are listed in `pyproject.toml`; the package is installed in editable mode with `.venv/Scripts/python.exe -m pip install -e ".[dev]"`.
- Windows host. Use the venv interpreter directly, without relying on activation:
  - Run the app (native window): `.venv/Scripts/python.exe main.py`
  - Tests: `.venv/Scripts/python.exe -m pytest` (UI tests use NiceGUI's `user_simulation`, with no browser)
  - Type check: `.venv/Scripts/python.exe -m mypy` (strict)
  - Lint and format: `.venv/Scripts/python.exe -m ruff check .` and `.venv/Scripts/python.exe -m ruff format .`
