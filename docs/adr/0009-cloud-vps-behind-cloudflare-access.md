# The app runs on an EU VPS behind Cloudflare Access, as the only copy of the data

ADR-0001 kept the app on the owner's Windows PC with no login and left room for a later move to a server. Stage 7 (#131) makes that move so the owner can use the app from a browser and a phone. It stays single-user. The app runs in Docker on a VPS in the EU (Hetzner or OVH). SQLite stays, in WAL mode, on a persistent volume. Moving to PostgreSQL waits until there is more than one user or more than one app process; multiple users (a `user_id` on every table) are out of scope. The only way in is a Cloudflare Tunnel, which `cloudflared` opens outwards from the VPS. The VPS opens no inbound port for the app, and Cloudflare serves HTTPS on the owner's own domain. A Cloudflare Access policy lets in only the owner's e-mail address, which signs in with a Google account (its 2FA applies) or a one-time PIN sent to that e-mail. The app does not trust the tunnel alone: it checks the `Cf-Access-Jwt-Assertion` token on every request (signature against the team's keys, audience, expiry) and refuses requests without a valid one. The app keeps no passwords of its own and has no 2FA of its own, so #142 is dropped and #133 shrinks to checking the token. The price is depending on Cloudflare: when Cloudflare is down, the app cannot be reached, and Cloudflare terminates TLS, so it sees the traffic. Secrets (the Stooq key, the NiceGUI storage secret, the Access audience) come from the environment, not the database. Backups are encrypted and leave the VPS. Once the data has moved (#140), the cloud copy is the only one: the native window mode stays for development and for running locally without login, with no sync between a local and the cloud database. That leaves the .exe installer (#99) with no clear purpose.
