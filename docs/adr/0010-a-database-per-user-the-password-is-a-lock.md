# Users: a database per User, the password is a lock

ADR-0001 made the app single-user; about ten people now use it, some of them sharing one computer and one Windows account, so the app gets Users (#177): a pseudonym and a password, chosen on a login screen at every start, with switching between Users in the same window. Each User has a folder of their own under the app-data folder, named by a fixed id, holding their whole SQLite database (settings, the Stooq key and every cache included), their backups and their log; only the list of Users (pseudonym, scrypt hash of the password) is shared, in the app-data folder itself. A `user_id` column on every table was rejected: every query in the app would have to filter on it, and one forgotten filter shows one User another's portfolio, while a database per User leaves the domain and the queries as they are and makes a backup or a deletion one folder. The password is a lock, not encryption: it keeps other people out of the app, not out of the files, which anyone with the Windows account can open. Encrypting the database (SQLCipher) was rejected for its cost and its Windows wheels for Python 3.14, and because a forgotten password would then lose the data; so a forgotten password is reset by hand, by removing its hash from the list of Users (the login screen explains how), and wrong passwords are not rate-limited.
