# Architecture by module

What each module of `src/financial_app/` does, its main functions and UI markers, and the issue or spec section it comes from. Each entry is a file in `docs/architecture/`, listed below by title. A module appears in every entry it takes part in: `grep -l "ui/transactions.py" docs/architecture/` lists them. Update those entries when you change the module; a new feature gets a new file and a line here.

Layout (`src/financial_app/`, see ADR-0001):
- `domain/`: pure-Python calculations. It must never import NiceGUI, SQLAlchemy, Alembic or pywebview; `tests/test_architecture.py` enforces this. `domain/formatting.py` is the single Polish number and date formatter (`format_pln`, `format_percent`, `format_quantity`, `format_unit_price`, `format_date`, `format_datetime`, `format_day_time` (day and month to the minute), `format_count` (Polish plurals), `format_exact` for edit fields, `format_exact_percent` for a stored percent like a TER and `format_points` for percentage points) and parser of typed input (`parse_number`, `parse_date`); use it for every amount or date shown in or read from the UI.
- `persistence/`: SQLite through SQLAlchemy. `models.py` holds the ORM models, each declaring `on_clear` (`OnClear.DELETE` for portfolio data that Wyczyść dane removes, `OnClear.KEEP` for caches, bond data and settings; issue #113), `migrations/` holds Alembic revisions, and `db.init_db(path)` applies them at start-up (`db.migrate(engine)` alone, e.g. on a test's in-memory database), right after `backup.backup_database` copies the file into `paths.backups_dir()` (newest 30 kept). The database lives in the user's app-data folder (`paths.data_dir()`, `%LOCALAPPDATA%\KAPITA`, overridable with `FINANCIAL_APP_DATA_DIR`; `paths.adopt_legacy_data_dir()` renames a pre-1.0 `FinancialApp` folder to it through `move_legacy_data_dir(legacy, current)`, which never touches an existing `current`), never in the repo. Change the schema only through a new migration: `.venv/Scripts/python.exe scripts/new_migration.py "..."` numbers it, autogenerates it against a scratch database (the CLI otherwise reads the real one) and runs ruff on it. `tests/test_database.py` fails if the models and migrations drift apart.
