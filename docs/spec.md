# Specification — Personal Investment Tracker

Status: agreed with the product owner on 2026-10-08 (design interview Q1–Q55). Vocabulary: see `CONTEXT.md`. Key decisions: `docs/adr/`.

## 1. Goal and scope

Re-implement the inwestomat.eu "Portfolio tracker" Google Sheet (v2.0.1, 01.07.2026; source copy and Apps Script in `reference/`, git-ignored) as a local desktop application with the **same functionality and calculation logic** and a better UI (forms, validation, filtering), then extend it beyond the sheet.

- Single user, local Windows PC, no login (Q1, Q8, Q29). Architecture must allow a later move to multiple users / a server (ADR-0001). Stage 7 moves the app to an EU VPS behind Cloudflare Access, still single-user; the cloud copy becomes the only copy of the data (ADR-0009).
- UI in Polish; code, DB names and technical docs in English (Q6).
- Spreadsheet bugs are fixed, not replicated; every fix that changes a number is a documented deviation (Q33, ADR-0004).
- Not needed: spreadsheet version check, migration between sheet versions, Apps Script triggers (Q37).

## 2. Architecture (Q13, Q26, Q10)

- Python 3.14, **NiceGUI** in native window mode, started from a desktop shortcut.
- **SQLite** via SQLAlchemy with schema migrations; DB file in the user's app-data folder, outside the repo.
- **Domain core**: pure Python package (no UI/DB imports) holding FIFO, valuation, cash, bonds, returns, benchmarks and tax logic. UI and persistence are thin layers around it.
- **Price Sources** and **Importers** are plug-in modules behind common interfaces.
- Automatic DB backup at every start, keeping the last 30 copies. Export of transactions to CSV and XLSX.
- Prices refresh at start (if older than the last market close) and on a "Odśwież" button, in the background; status and errors shown on the Dashboard (Q24).

## 3. Data model

### 3.1 Accounts (Q14, Q48, Q49)
- Managed list (not free text). Fields: name, broker name, Account Type, Cash Currencies (e.g. PLN only, or PLN+USD), optional FX Conversion Fee % (e.g. XTB 0.5%; empty for most accounts), flag "exclude FX result from Dashboard P&L", active/inactive.
- **Deleting** (L-28, #103): the edit dialog's "Usuń konto" deletes an Account after a confirmation naming it, only while nothing names it: its own Transactions, Cash or Security Transfers into it, its own Investment Strategy or an XTB account number mapped to it; otherwise a Polish message says what holds it, and deactivating stays the way to hide it. A View Scope on it goes back to Total.
- Account Types: Regular, IKE, IKZE, OIPE, PPK, OKI, Deposit/Savings, Bonds, Other (#64). Each type maps to a **Tax Regime** module:
  - Regular: 19% Belka per sale, reported in PIT-38.
  - IKE/OIPE: exempt on a qualifying withdrawal, otherwise tax on the whole gain.
  - IKZE: contributions deductible, 10% flat tax at withdrawal.
  - PPK: own rules.
  - Deposit/Savings: 19% Belka on interest, withheld by the bank.
  - Bonds (a retail treasury bond register, e.g. PKO BP): 19% Belka on interest and the gain at redemption, withheld by the issuer, outside PIT-38. Bonds held on an IKE stay on an IKE Account.
  - Other (assets held outside a financial institution, e.g. physical metals at home): no Belka; selling a thing within 6 months from the end of the month it was bought is taxed at the PIT scale, later it is exempt. Description only until Stage 6.
  - **OKI: placeholder** — no calculation, UI note that rules will be added once the law is final. From the start the app keeps everything a future OKI rule might need: Transactions, daily Account value (from History), Deposits/Withdrawals.

### 3.2 Instruments (Q15, Q16, Q46, Q21)
- Catalog entity: name, Asset Class, quote currency, market, Source Symbol per Price Source, optional Manual Price.
- Physical metals: weight per unit in grams and Buyback Spread %. Primary value = spot × weight × (1 − spread); spot value shown as secondary (Q46).
- Asset Classes: user-editable list, seeded with the sheet's 12: Gotówka, Akcje polskie, Akcje zagraniczne, Obligacje skarbowe polskie, Obligacje skarbowe zagraniczne, Obligacje korporacyjne polskie, Obligacje korporacyjne zagraniczne, Metale i surowce, Kryptowaluty, Waluty, Inne, Multi-asset. Renaming must not require code changes.
- Multi-asset Split per Instrument; cannot be saved unless it sums to 100%. Buying an unconfigured Multi-asset Instrument opens the split dialog (Q41).
- Allocation Target % per Asset Class; warning (not block) when targets ≠ 100% (Q41).
- Currencies: base PLN; any NBP table-A currency. Base-currency change is designed for but not built (Q16).

### 3.3 Transactions (Q22, Q23, Q37, Q38, Q50)
Types: Deposit (Wpłata), Withdrawal (Wypłata), Buy (Zakup), Sell (Sprzedaż), Dividend/Interest (gross, withholding tax, net), Cost (Koszty), Split (X:Y), Currency Exchange (Wymiana walut), Cash Transfer (PLN, or a foreign Cash Currency both Accounts hold, worth its amount at NBP D-1, moving its cash Lots with their dates and costs, #125), Security Transfer (keeps Lot dates and costs), DRIP.

Each Transaction stores:
- account, date, instrument, quantity, price (instrument currency; a Catalyst bond's price per bond, its percent of nominal times the nominal, L-23), commission (any currency), comment;
- **Actual Amount** (PLN that really moved; entered or derived from the user's rate) and **Tax Amount** (at NBP D-1) (Q38);
- FX Conversion Fee amount when an automatic conversion happened;
- **Origin**: manual / spreadsheet import / broker import, plus external id (e.g. XTB order number) and reconciliation date (Q52, Q53).

FX conversion on a PLN-only Account (Q49, Q50, Q50b, Q56, prototype verdict): conversion happens only when a Buy/Sell/Dividend is in a currency the Account does not hold.
- By default the form shows a rate field (`Kurs USD/PLN`, empty = NBP D-1); Actual Amount = quantity × price × rate ± commission.
- Below the commission, a checkbox "Prowizja <broker> (przewalutowanie X%)" appears **only on Accounts with an FX Conversion Fee configured**, **unchecked by default**. When checked, the user **must enter the PLN amount charged by the broker**; the app derives the effective rate and the fee and records the fee as a Cost (Dashboard "Prowizje i koszty"; deductible cost in PIT-38 for Regular accounts).
- On an Account with a matching Cash Currency the user chooses the payment source (foreign cash, or PLN with conversion). The form offers "exchange currency automatically" to create Currency Exchange + Buy in one go (Q19).
- On an Account with a foreign Cash Currency a Deposit, Withdrawal or Cost may be in it ("Waluta", PLN by default) (#119). A foreign Deposit or Withdrawal counts in PLN (Net Deposits, Contribution Limits) at the user's `Kurs USD/PLN` or, empty, the NBP Rate D-1, its Tax Amount at the NBP Rate; a Deposit opens a foreign-cash Lot like an Exchange, a Withdrawal closes the oldest Lots and realises the FX result. A foreign Cost counts at the NBP Rate only.
- A Buy offers "Kwota do wydania" in the currency it is paid from (#120), a helper not saved: it proposes the quantity ⌊(amount − commission) ÷ (rate × (1 + FX Conversion Fee %)) ÷ price⌋, rounded down to the Instrument's decimal places (the rate: 1 when paid from the Instrument's own currency, else the user's rate or the NBP Rate D-1; the fee only when the broker converts; the PLN commission is not taken from a foreign amount). The proposal fills the quantity until the user types one of their own.

Validation at save time (Q36):
- Block: selling more than held on that Account at that date; Split before the first Buy or malformed ratio; missing NBP rate (never silently 0 PLN).
- Warn only: insufficient cash (allows entering history in any order) (Q19).

### 3.3.1 Recurring Rules (#97, 2026-10-17)
- **Rule**: a Recurring Rule has a name, an Account, a type (Deposit, Buy, Cost or Cash Transfer (#147); nothing else, no Withdrawal), the Instrument of a Buy, the target Account of a Cash Transfer, an amount in one of the Account's Cash Currencies, a frequency (monthly, quarterly, half-yearly, yearly, counted from the start date's month), a day of the month, a start date, an optional end date and an active flag. It is stored (with its skipped occurrences); clearing the data removes both, and so does deleting its Account or a Cash Transfer's target Account.
- **Occurrences**: from the start date to the earlier of today and the end date; a day past the month's end falls on its last day, and one on a Saturday or Sunday moves to the next Monday (no public holidays), possibly into the next month. A new rule starts at its next occurrence by default, so it brings no backlog. An inactive rule has none.
- **Matching**: an occurrence is covered by the Transaction saved from its Draft (the Transaction stores the rule and the occurrence date, so editing it later changes nothing; deleting the rule leaves the Transaction, unlinked). Otherwise any Transaction entered by hand or imported (XTB) on the same Account, of the same type, (for a Buy) Instrument (for a Bond Series: of the same bond type, any month's Series, #149) and (for a Cash Transfer) target Account, within ±7 days of the occurrence and not linked to an occurrence covers it, the amount not compared; occurrences take the nearest free Transaction, oldest first, one Transaction covering at most one occurrence. Computed, never stored.
- **Drafts**: each uncovered, unskipped occurrence is a Draft, kept apart from the bond Drafts: a list "Transakcje cykliczne do zatwierdzenia" above the Transakcje tab's table, oldest first, following the View Scope (a Cash Transfer's in the View of either Account), and a header button "Cykliczne do zatwierdzenia: n" over every Account that opens it; the bond list and its "Do zatwierdzenia: n" stay as they are. A row shows the day, the rule's name, Account, type, Instrument and amount. A Deposit, Cost or Cash Transfer has "Zatwierdź" (saves it on the occurrence day with the rule's amount, currency and target Account, a foreign currency at the NBP Rate D-1, Origin manual) and "Edytuj…" (the "+" dialog prefilled with the same, saving on its own "Zapisz"); a Buy only "Edytuj…", the dialog prefilled with the Account, Instrument (for a Bond Series, the Series of its bond type sold in the occurrence's month) and day, its quantity and price left empty. "Pomiń" skips the occurrence for good. There is no "confirm all".
- **Rules in Ustawienia**: a card "Transakcje cykliczne", a table of the rules (name, Account, type, Instrument (a Bond Series rule shows its bond type), amount, frequency, next occurrence, active) with add, edit, switch off and delete; the rule's dialog lists its skipped occurrences with "Przywróć" and has "Pomiń zaległe" to skip every uncovered occurrence before today. A Deposit, Buy, Cost or Cash Transfer in the Transakcje tab offers "Powtarzaj…", a new rule prefilled from it (a Buy's amount being its Actual Amount, a Cash Transfer's target Account carried over), starting at the next occurrence after today (after the Transaction, if dated ahead), so that repeating an old Transaction brings no overdue Drafts.
- **Investment Goal** (#148): the forecast's default monthly deposit comes from the active rules (not ended before today; one starting ahead counts) when the View Scope has at least one: in Total every Deposit rule, in an Account's View its Deposit rules plus the Cash Transfer rules into it, less those out of it (as its Net Deposits count them). Per month: monthly × 1, quarterly / 3, half-yearly / 6, yearly / 12; a foreign currency at the latest NBP Rate (a rule without one is left out). Buy and Cost rules do not count (a Buy spends cash already deposited, a Cost leaves Net Deposits alone). Without such a rule the default stays the average Net Deposits of the last 12 months; a monthly deposit typed in the goal's dialog overrides either. The dialog says where the default comes from: "z reguł cyklicznych" or "średnia z 12 miesięcy".
- **Out of scope**: Drafts do not count towards Contribution Limits.

### 3.3.2 Term Deposits (#160, 2026-10-19)
- **Deposit**: a Term Deposit sits on an active Account of the Deposit type holding PLN. It has a name, a principal (to the grosz), a start date, a term (a number of months, or of days for any other maturity), an annual rate (%), its capitalisation (at maturity, monthly, quarterly, half-yearly, yearly; no daily capitalisation, which would draft interest every day), whether it renews and, once ended, the day it closed. Maturity is the start plus the term (months counted to the same day, the month's last day when shorter). It is stored; clearing the data and deleting its Account remove it, deleting it leaves its interest unlinked. Its capital is only recorded as cash (a Deposit or a Cash Transfer into the Account, offered by its dialog: the Deposit by default when the Account's cash at the end of the start day is below the principal, else nothing; the deposit itself is no Transaction, as the dialog says); PLN only for now.
- **Interest**: per capitalisation period, ending every 1, 3, 6 or 12 months counted from the start (the last on maturity): capital × rate × the period's actual days / 365, rounded half up to the grosz; Belka at the Account's withheld rate (19%), rounded to the grosz. A period capitalised before maturity adds its net interest to the next period's capital. Breaking the deposit forfeits the period running then, so History no longer accrues it on the days before the break either (the value is what the bank pays); interest the bank still pays on breaking is entered with "+" as interest.
- **Drafts**: each period ended and not paid is a Draft ("Zatwierdź odsetki": interest, no Instrument, gross and tax, on the period's last day, linked to the deposit and period; "Edytuj…": the same with the bank's day and amounts). Linked interest pays its period whatever its day; otherwise interest entered by hand or imported (no Instrument, no Lot, no link) on the deposit's Account within ±7 days of the period's end pays it (as a Recurring Rule's matching window, since banks credit around the day), the nearest free one, amounts not compared; interest paid before its period ended stops accruing from its day. A deposit past maturity and not closed is a maturity Draft: "Zakończ" closes it on maturity; "Odnów…" closes it and starts the same deposit from maturity, of the principal plus every period's net interest, at the rate typed (by default its own). Nothing renews by itself, even a renewable deposit (whose Draft offers "Odnów" first); after maturity no interest accrues until it is renewed. The Drafts join the bonds' "Do zatwierdzenia" list and header count.
- **Value**: an Account's value includes the Accrued Interest net of Belka (each period ended and not paid by that day, and the running period's days so far, rounded to the grosz), as cash: the Dashboard, Portfolio, the Account ranking, Valuation Snapshots, History and so XIRR and TWR count it, and the profit-by-source waterfall shows it gross as interest with its tax. Belka on deposits is withheld at source, so it is not in the estimated tax. The deposits' list shows, besides, what breaking one today pays (the principal and the net interest of the periods ended).
- **Warning**: a save after which an Account's PLN cash on a day it touched is below the principal of its deposits running then, and was not before, warns ("Jeśli lokata została zerwana, zaznacz to…"), never blocks.
- **Passive income**: interest linked to a deposit is "Odsetki z lokat"; its periods not paid yet over the next 12 months are forecast.

### 3.4 Bonds (Q17, Q34, Q45)
- Instrument = **Bond Series** in MF convention `TYPYMMRR` (type + maturity month + 2-digit maturity year, e.g. EDO bought 07.2025 → `EDO0735`). A series is sold in one month only, so its first-year rate, margin and the rates of later periods belong to the Series; each purchase is its own Lot with its date (its anniversaries count from it), quantity and price (100, or the Rollover price).
- Supported: OTS, TOS, COI, EDO, ROS, ROD, ROR, DOR, all valued automatically.
- Rates: **MF-published rate is authoritative**; max(0, CPI(YoY, month = anniversary − 2) − 100) + margin (deflation leaves the margin, as MF paid in 2015–16), only for unpublished periods and flagged **Estimated**. Valuations show whether they rest on official or estimated rates.
- Valuation by the MF issue letters (3.4.1), not the sheet's whole-amount accrual: linear accrual within a period; EDO/ROS/ROD compound annually; COI coupons paid out (base stays nominal) and tracked net of 19%; TOS fixed rate compounding.
- Extras: net value after early-redemption fee and Belka tax; calendar of coupon payments and maturities; sale picks a specific Lot (default oldest, ADR-0007).
- Rollover price from the MF file (default 99.90).

### 3.4.1 Stage 3 decisions (grilling of #4, 2026-10-12)
- **Scope**: the retail treasury bonds OTS, TOS, COI, EDO, ROS, ROD, ROR and DOR, in slices: EDO end to end first, then ROS/ROD and TOS/OTS, then the coupon types COI/ROR/DOR. Catalyst prices and accrued interest (gpwcatalyst.pl) and the gov.pl IZ indexed nominal left Stage 3 for L-23 and L-24 (section 4.2).
- **Rates on the Series**: first-year rate, margin and each period's rate are stored on the Bond Series, fetched from the MF file and correctable by hand.
- **Valuation per bond, as MF**: the value of one bond is computed with the MF rounding to the grosz, then multiplied by the quantity (for EDO the yearly rates compound unrounded and the bond is rounded once, which reproduces the interest of every matured EDO in the MF file); Belka is computed on the profit of one bond. The differences from the sheet are a documented deviation (section 9).
- **Rate labels**: an MF-published rate has none. For a period MF has not published yet, "szacowana (CPI)" when GUS has published the CPI of the right month (or "szacowana (NBP)" for ROR/DOR from the NBP reference rate in force), "prognoza (ostatnie CPI)" or "prognoza (ostatnia stopa NBP)" when it has not and the last known one stands in. The label goes once MF publishes the rate.
- **Value shown**: gross (nominal plus accrued interest) in the Portfolio, Dashboard and History, as other assets. The net value (after the early-redemption fee and the Tax Regime's tax) is shown in the Obligacje tab and feeds the after-tax toggle (#89).
- **Tax by Account**: the net value, the Drafts and an early redemption take the tax from the Account's Tax Regime: Belka withheld at redemption on a Bonds or Regular Account, none on IKE/IKZE. The early-redemption fee applies everywhere, capped at the accrued interest as the issue letters say.
- **Early-redemption fees**: a table built into the app (bond type, first issue it applies to, amount), updated with app releases, unless the MF file carries the fee.
- **Entering a purchase**: the ordinary "+" dialog in a bond mode: type and purchase date give the Series (created on its first purchase), the price is 100 or, with "z rolowania", the MF Rollover price. An older purchase may pick any Series of the type from the MF copy (L-26, #102; searchable, the newest sold first, the date's own by default); a date outside that Series' sale window only warns, a Rollover up to 7 days after it. The MF file also lists types no longer sold (KOS, POS, IR, RS, DOS, TOZ, TZ, SP); they are not offered, since their terms and valuation differ and none is held.
- **Early redemption**: a Sell of a Bond Series picks the Lot (default the oldest, ADR-0007), prefilled with the gross value of one bond on that day as the price, the early-redemption fee as the commission and the tax as withheld tax; all editable to match the bank's statement, the Actual Amount being the net received.
- **Drafts**: a matured Series and (for COI, ROR, DOR) a due coupon without a matching Transaction show as a Draft in the Obligacje tab's "Do zatwierdzenia" list, with a count in the header. Drafts are computed, never stored; confirming one saves an ordinary Transaction. A coupon is an interest Dividend (no Instrument) with Belka as withholding tax, into the PLN cash of the Account holding the Series. A Rollover is one action ("roluj do…") saving the redemption and the purchase of the new Series.
- **History**: Bond Series are valued day by day with the same function as today, Estimated and forecast rates included; the bond deviation of the Historia parity test goes.
- **Existing Series**: a migration clears the Manual Prices of retail treasury Bond Series (from the Stage 1 import) so automatic valuation takes over; a Manual Price can still be set as an override, and the sheet import stops setting one.
- **Sources**: the MF file (gov.pl), GUS CPI and the NBP reference rate history, fetched with the price refresh at start-up and from the header button at most once a day, kept in SQLite; a failure shows in the header status like prices and the last copy is used.
- **Obligacje tab** (follows the View Scope): the "Do zatwierdzenia" list when not empty; a table of Series expanding to Lots (Series, quantity, paid in, current period and its rate with its label, gross value, net value, next anniversary, maturity); a calendar of coupons, anniversaries with a new rate and maturities over the next 12 months, which later feeds the Stage 5 passive-income calendar.
- **Obligacje tab and Net Value (L-4)**: one row per Bond Series and Account (largest gross value first; the Account named in Total), clicking it shows its Lots, then the sums. The period, rate and label are the oldest Lot's (the label the most uncertain of any Lot); the next anniversary and the maturity the earliest Lot's. The Net Value is computed per bond: the early-redemption fee from the built-in table (`domain/bond_redemption.py`: ROR 0.50, DOR 0.70, OTS none; TOS 0.70, COI 0.70, ROS 0.70, EDO 2.00, ROD 2.00 zł, raised from the September 2024 issues to TOS 1.00, COI 2.00, ROS 2.00, EDO 3.00, ROD 3.00 zł; an issue is dated by its month of sale), capped at the accrued interest over the nominal, none from maturity; then the Tax Regime's withheld tax (19% on Regular, Bonds, Deposit, Other and, until its rules are in, OKI; none on IKE, IKZE, OIPE, PPK) on the bond's profit over its Tax cost after the fee, rounded half up to the grosz, so a Rollover purchase at 99.90 is taxed on its discount too. A Series not valued yet stays at cost without a Net Value. The tab values Series by the MF issue letters even while a Manual Price overrides them elsewhere. The Dashboard's "po podatku" toggle takes each valued Bond Series' gross less Net Value (fee and tax) into the estimate, outside the PIT-38 offset of Regular gains and losses (Belka withheld at source cannot be offset), so the fee too lands under the waterfall's taxes; its tile reads "Szacowany podatek i opłaty". A Series under a Manual Price counts in the toggle like any other Instrument (the user's price, no fee), while the tab keeps the MF valuation.
- **Early Redemption (L-5)**: the Sell stores the Lot it names (the Transaction that opened it) and the tax withheld; the FIFO engine takes its units from that Lot alone and blocks the Sell once the Lot is gone, so the Lot's Buy cannot be deleted while a redemption names it. The dialog's prefill (the Lot's bonds, the gross value of one bond, the fee and tax for all the bonds, by the Net Value's rules) never overwrites a value the user typed. The withheld tax counts under taxes in the waterfall, the fee under costs.
- **Maturity and Rollover (L-6)**: each Lot of a Bond Series still held on or after its own maturity (purchase day + term) is a Draft, earliest first, following the View Scope; the header's "Do zatwierdzenia: n" counts every Account's and opens the tab. Confirming its redemption saves a Sell naming the Lot, on the maturity day, of all its bonds at one bond's maturity value, no fee, the Tax Regime's tax withheld. "Roluj do…" picks the type (any but the family ROS/ROD, which the app never buys in a Rollover; the matured type by default, EDO for a matured ROS/ROD) and the number of bonds (at most the Lot's, which it is by default) and saves that Sell with the Buy of the Series sold that month, on the same day at its MF Rollover price (99.90 without one), both or neither. A Series not valued yet shows its Draft without buttons, entered by hand with "+". To change the amounts to the bank's statement, the saved Transactions are edited as any other.
- **ROS, ROD, TOS, OTS (L-7)**: ROS and ROD are valued as EDO (yearly rates, CPI + margin after the first, compounded unrounded, the bond rounded once); TOS compounds its one fixed rate yearly the same way; the three-month OTS earns its rate over its days out of 365 (100 × rate × days / 365, rounded once). Every matured TOS, ROS and OTS in the MF file pays exactly that (the file's interest is for a purchase on the first day of sale; an OTS bought on a month's last day runs fewer days to the shorter month's end and earns that much less). TOS has no next anniversary in the Obligacje tab, its rate never changing; the L-9 calendar may still show its yearly capitalisation. An OTS redeemed early pays no fee but forfeits its interest, so its Net Value before maturity is its nominal: the forfeited interest counts as its fee (in the Net Value, the after-tax toggle and the Sell prefill). An OTS's rate shows without a year. The coupon types COI, ROR and DOR stay at cost ("do etapu 3") until L-8.
- **COI, ROR, DOR (L-8)**: the coupon types pay each period's interest out instead of compounding it: a coupon of 100 × the rate for the period's share of a year (COI yearly, 100 × rate; ROR and DOR monthly, 100 × rate / 12), rounded half up to the grosz, as every coupon in the MF file is (the COI of 1999-2003, which paid everything at maturity, aside). Between coupons a bond is worth its nominal plus the current period's coupon accrued linearly over the period's days; the last coupon comes with the nominal at maturity, in the maturity Draft's redemption. A COI year MF has not published is estimated from CPI as EDO; a ROR or DOR month from the NBP reference rate (floored at 0) in force ten business days (weekdays) before the first day of the calendar month the period starts in, plus the margin, labelled "szacowana (NBP)", or "prognoza (ostatnia stopa NBP)" when that day is after the saved NBP copy was last fetched (every ROR and DOR month in the MF file matches; NBP changes take effect early in a month, so the exact day never mattered so far). The rate shows as "<rate> · miesiąc <n>" for ROR and DOR. Each coupon paid by today (before maturity) of a Lot still held is a Draft ("Odsetki <Series>", the period and day, the net payout and the tax) until entered: confirming saves an interest Dividend (no Instrument, `lot_id` the Lot's Buy, on the coupon's day, gross the coupon of all its bonds, the Tax Regime's tax on the coupon of one bond, rounded half up, times the bonds). The interest Dividends naming a Lot enter its coupons oldest first, whatever their day, so editing one to the bank's statement (day or amounts) keeps it entered, and the dialog keeps the Lot when interest is edited as interest. The Lot's Buy cannot be deleted while interest names it. A coupon is drafted for the bonds the Lot holds now; interest entered without naming the Lot (as the sheet import saves it) does not count, so its coupons show as Drafts (no held coupon type in the sheet so far). The "do etapu 3" badge remains only for a treasury bond that is no Bond Series.
- **Calendar (L-9)**: below the Obligacje tab's table, following the View Scope, one row per Lot and event from tomorrow to the same day next year (what falls due today is already a Draft), by day: each coupon (COI, ROR, DOR) with its rate and label, the gross for the Lot's bonds and the net after the Tax Regime's tax on the coupon of one bond, as its Draft will save it; each yearly anniversary before maturity (EDO, ROS, ROD, COI; TOS capitalising its fixed rate) with the new period's rate and label, no amount; the maturity with the nominal and interest of the Lot's bonds and the net after the tax, as the maturity Draft redeems it. The monthly ROR and DOR show their rate on each coupon instead of an anniversary. A Series not valued yet shows only its maturity, without amounts. `domain/bond_calendar.py` `bond_calendar` gives the events, which the Stage 5 passive-income calendar will take.
- **Real return (L-10)**: Wyniki shows the TWR over the period after the period's inflation, (1 + TWR) / (1 + inflation) − 1. As in the sheet's Benchmarki, the GUS month-on-month CPI (previous month = 100) is spread evenly across the month's days, compounding day by day, over the days after the "from" day up to the "to" day, and a month GUS has not published adds none. The tile's note gives the period's inflation, "inflacja (CPI) x %", followed by "· CPI do <MM.RRRR>" (the last published month) when part of the period is unpublished; with no month of the period published the tile shows "—" and "brak CPI GUS za ten okres". Inflation counts from the day the View Scope first held something within the period, as the TWR does. It follows the saved GUS copy, redrawn after the bond data refresh.
- **Bond parity (L-11)**: the sheet values EDO, ROS, ROD and COI with one set of yearly formulas and TOS with its own, and has no OTS, ROR or DOR. The parity test compares every row of the user's Obligacje tab with the app within 0.01 PLN per bond (only EDO is held so far), and each type the sheet values with the tab's formulas re-stated, on every 10th day from the purchase past the maturity; they differ only by the app's rounding of one bond (section 9, item 18), a TOS also after its maturity (item 19).
- **Testing**: unit tests on worked examples from the MF issue letters (several types, anniversaries, early redemption, Rollover), and a parity test against the sheet's Obligacje tab within 0.01 PLN per bond, skipped without `reference/`, each larger difference recorded in section 9.
- **Slices**: (1) sources: MF file, GUS CPI, NBP reference rate; (2) Bond Series with rates, the dialog's bond mode, the Manual Price migration, the import without a Manual Price; (3) EDO valuation in the Portfolio, Dashboard and History with the parity test; (4) Obligacje tab with the net value and the after-tax toggle; (5) early redemption with the Lot choice and the fee table; (6) maturity and Rollover as Drafts with the header count; (7) ROS, ROD, TOS, OTS; (8) COI, ROR, DOR coupons as Drafts; (9) the calendar; (10) the real return in Wyniki; (11) bond parity with the sheet across the types it values.

### 3.5 FIFO and cash (Q20, Q31, Q32, ADR-0003)
- One lot engine for Portfolio, Sell Summary and PIT-38. FIFO only.
- Lot key: Account + Instrument. Same-day order: Split, Buy, Security Transfer, Sell, DRIP/Deposit.
- Buy fee capitalised into Lot cost; each Lot carries Actual cost and Tax cost (qty × price × NBP D-1 + fee in PLN).
- Splits rescale open Lots (qty × X/Y, unit price × Y/X); fees are not rescaled.
- Cash Balance per Account and Cash Currency; foreign cash held as Lots with PLN cost → FX result per Account, excludable by the Account flag. Commission paid in PLN is not counted in the foreign-cash quantity. An Account without PLN (#124) pays its commission from the foreign cash the trade is paid from, so it is counted there, valued at the trade's rate (the Tax Amount at NBP D-1); it has no Currency Exchange, PLN Cash Transfer or broker conversion. A Cash Transfer in a foreign currency (#125) moves the source's oldest cash Lots to the target with their dates and costs, realising no FX result; a shortfall arrives at the NBP value, leaving a negative Lot behind.
- Dividend attribution to sold pairs (Sell Summary): pro-rata by quantity held on the dividend date, with split-adjusted units.

### 4.1 Automatic valuation rules (grilling of #3 and #25)
- **Manual Price wins while set**; the automatic Quote is still fetched and shown beside it. Clearing the Manual Price returns the Instrument to automatic valuation. A Bond Series is valued from MF data (3.4.1), every type since L-8; a Manual Price still overrides it ("ręczna"), a Series without its first rate stays at cost marked "brak oprocentowania"; another treasury bond (no Bond Series, e.g. DS or IZ on Catalyst) is quoted like any Instrument (4.2).
- **Source Symbols** are a list per Instrument (one per Price Source), entered in the Instrument dialog with a "Sprawdź" button that fetches one Quote (price, currency, date) and warns on a currency mismatch; saving is allowed when the check fails. Imported Instruments start without Source Symbols; an "Instrumenty bez wyceny" list leads through them.
- **Fallback Order** per Asset Class, edited in Ustawienia > Klasy aktywów (add, remove or reorder sources; a new class starts with the order of "Inne"; clearing the data restores the defaults); an Instrument uses only the sources it has a Source Symbol for, in that order, with no per-Instrument override. Defaults: Akcje polskie Bossa → Yahoo; Akcje zagraniczne Yahoo → Bossa; Obligacje skarbowe polskie and Obligacje korporacyjne polskie Bossa (Catalyst; Bond Series are valued from MF data whatever the order); Obligacje skarbowe/korporacyjne zagraniczne, Metale i surowce, Kryptowaluty Yahoo; Multi-asset, Inne and classes the user adds analizy.pl → bankier.pl → Yahoo → Bossa; Gotówka, Waluty none. Stooq serves history and indices only (#33), through the user's personal Stooq API key entered in Ustawienia; History asks for an Instrument's Quotes or a currency's NBP Rates in a date range and only days not fetched yet are fetched, up to yesterday.
- **Currency**: a source module returns the price in the Instrument's quote currency (GBp ÷ 100, crypto via USD cross) or an error; a mismatch is shown, never converted silently. Foreign Positions are valued at the latest NBP Rate.
- **Quotes**: one table of daily Quotes (Instrument, day, price, Price Source, fetch time); the current price is the newest Quote, a same-day refresh overwrites it, and History (Etap 4) fills older days into the same table.
- **Refresh**: in the background at start-up when the last successful refresh (one where not every Instrument failed) was before the most recent weekday close (17:30, after the GPW closing auction), and on demand from the header; only Instruments with an open Position are fetched. A price is **Stale** only when the latest attempt failed in every source; the Quote date is always shown, so no exchange calendar is needed.
- **Status**: the header shows "Wyceny: <time>" with a refresh button, red with the number of errors, listing failing Instruments and reasons; each Portfolio Position shows the Quote date and a badge (ręczna, nieaktualna, bez źródła, brak oprocentowania).
- **Physical metals**: optional metal weight per unit in grams (exact decimal, 31.1034768 g/oz) and Buyback Spread %; value = spot (USD/oz) × weight × (1 − spread) at the NBP Rate, spot shown alongside. With a weight set, the Instrument's Quotes and Manual Price are the spot of a troy ounce in its quote currency (so a Yahoo-priced metal is quoted in USD); without one it is valued per unit as usual.
- **ISIN lookup (#25)**: Instruments get an optional, non-unique ISIN (each listing is its own Instrument). One search field "Szukaj (ISIN, nazwa lub symbol)" in the Instrument dialog, on create and edit, prefilled with the name of an Instrument without Source Symbols; it queries Yahoo search behind a swappable module, and a chosen result fills only empty fields (ISIN, quote currency, market, Yahoo and Bossa Source Symbols). Polish funds stay manual. TER, Distribution Policy and domicile are user-entered Instrument fields shown in the Portfolio; scraping them (e.g. justETF) is out of scope under ADR-0005.


### 4.2 Catalyst bonds (L-23, L-24)
- **Price per bond**: Bossa quotes a Catalyst bond as a percent of its nominal without accrued interest (the clean price), so its Quote is that percent times the bond's nominal / 100 plus the interest accrued on one bond, in PLN (the sheet's value of a bond, "Obecna Wartość PLN"). The Quote keeps Bossa's day; gpwcatalyst.pl gives only today's nominal and interest, so across a coupon date a Quote of an earlier day is off by the coupon until the next refresh, while an IZ bond takes those of the Quote's day. A bond whose nominal cannot be had gets no Quote (that source fails for it), never a percent. A migration drops the Bossa Quotes of the Polish bond classes, saved before as percents (a Catalyst bond kept in another class keeps them), and gives "Obligacje skarbowe polskie" the Fallback Order Bossa when it is empty (an order the user emptied cannot be told apart). History values a treasury bond that is no Bond Series at its Quotes, so at cost, listed as unpriced, on the days before its first Quote.
- **Nominal and accrued interest**: from the gpwcatalyst.pl page "Instrumenty notowane" (its table of bonds in PLN: "Wartość nominalna", "Odsetki skumulowane (PLN)"), fetched once a refresh, as the sheet does. gpwcatalyst.pl's own quote pages are not used: Bossa lists every Catalyst bond and those pages often time out.
- **IZ indexed nominal**: an IZ bond (IZ0831, IZ0836) takes its nominal as 1000 zł times the indexation coefficient of the Quote's day, rounded half up to the grosz, and that day's accrued interest from the MF table "Współczynniki indeksacji" on gov.pl (two months of days; the last day before it, up to a week, when the day is missing); without it, gpwcatalyst.pl's nominal and interest stand in.
- **Entering a trade**: the "+" dialog takes a Catalyst bond's price per bond (as the broker's statement). The sheet import reads the optional column "Cena nominalna": a nominal over 1 makes the row's "Cena", a percent, a price per bond (Cena × nominal / 100); the accrued interest paid is not in the sheet's "Cena".

### 6.1 Stage 4 decisions (grilling of #5, 2026-10-11)
- **Order**: Stage 4 runs before Stage 3. Slices: (a) History engine (daily value per Account and Asset Class, Net Deposits; no UI), (b) metrics (XIRR, TWR, drawdown, volatility), (j) Historia parity test right after (a)+(b), then (c) View Scope switcher and period selector, (d) Dashboard totals, Account table, currency exposure, (e) charts, (f) Wyniki tab, (g) Multi-asset; (h) Investment Strategies last as a separate slice. Benchmarks stay in Stage 5 (#6); treemap, Account ranking, profit-by-source waterfall and after-tax toggle come after (h).
- **Quote history sources** (ADR-0006): Yahoo chart history first (it knows the currency, GBp ÷ 100), then analizy.pl for funds and PPK (#101), Stooq as fallback, in a per-Asset-Class history order like the price Fallback Order. Yahoo `close` (split-adjusted only), never `adjclose`: Dividends come from Transactions.
- **Splits**: history prices are split-adjusted, so before a Split's date History divides the price by the Splits recorded in Transactions (un-adjusts it). An unrecorded split shows as a jump caught by the parity test.
- **Missing days**: the last known Quote and NBP Rate carry forward; with none on or before the day, the Position is valued at cost and flagged "brak ceny". Bond Series are valued by the MF issue letters with today's known rates (3.4.1), Estimated and forecast ones included; a type not valued yet stays at cost (nominal).
- **FX on day D**: valuation uses the NBP table of day D (else the latest earlier); D-1 stays only for tax costs.
- **Fetching**: history is fetched in the background after start (after the price refresh), header status "Historia: pobieranie… (n/N)", failures listed like "Wyceny"; later only missing days are fetched.
- **Computing**: in memory in `run.cpu_bound`, cached until a Transaction save or price refresh; nothing stored (ADR-0002).
- **Flows**: Total: Deposits and Withdrawals; Account scope also Cash and Security Transfers, a Security Transfer valued at its market value that day (cost without a price). TWR: flows at end of day, daily return (V_D − F_D) / V_{D−1} − 1.
- **Periods**: XIRR over a period takes the value on the "from" day as an initial deposit and the "to" value as the final withdrawal; TWR chains daily returns; a period before the first Transaction is clipped to it.
- **Volatility**: from weekday (Mon–Fri) daily TWR returns, annualised by √252.
- **Real return**: the TWR after the GUS CPI's inflation over the period (3.4.1, L-10).
- **Multi-asset Split** (#75): one fixed split per Instrument (percent per Asset Class, summing to 100%), applied to all of History (documented simplification); an Instrument without one stays in Multi-asset. The Multi-asset class is marked as such, so renaming it changes nothing. The split is entered in the Instrument dialog while the class is Multi-asset (an Instrument moved to another class loses its split), in the split dialog that saving a Buy or DRIP (new or edited) of a Multi-asset Instrument without one opens, and from the Multi-asset tab; an import never asks, it names the Multi-asset Instruments left without a split. The tab lists the View Scope's Multi-asset Instruments with today's value per class and the classes' sums. History, the Dashboard allocation and the class-share chart count each class's part; a class in a split cannot be deleted.
- **View Scope** is remembered in `app_settings` (`view_scope`: `total` or an Account id), falling back to Total if the Account is gone. Daily change = V_today − V_yesterday − today's flows, "—" while history loads.
- **Dashboard** (#72): like the sheet, "Gotówka" is the PLN Cash Balance and "Otwarte pozycje" also holds the foreign cash; Net Deposits come from History; XIRR ends at today's value as the Dashboard shows it (Manual Prices included, which History does not know yet), so Wyniki may differ until it does. The Account table hides an inactive Account once it holds nothing.
- **Allocation chart** shows current class shares (with Multi-asset Splits) and, once the View Scope's strategy has them, its Allocation Targets beside them (#76).
- **Dashboard charts** (#73): ECharts (`ui.echart`), each following the View Scope and the period. Like the sheet, value vs Net Deposits and P&L (value − Net Deposits) are each day's own, cropped to the period; XIRR (from the "from" day to each day, at most 200 days evenly spaced) and drawdown start at the "from" day. Asset Class share over time takes the last day of each month, quarter, half-year or year (the switch is not remembered); Dividends are the net ones paid in the period, by year, stacked per Account; Account values (open Positions + cash), allocation and the currency doughnut are today's, as in the totals. The allocation counts the Multi-asset Splits (#75).
- **Wyniki** (#74): over the chosen period the View Scope's XIRR (annual), TWR (for the period), the deepest drawdown of the TWR with its peak and trough, the recovery days (from the trough until the TWR is back at its peak, "nie odrobione" until then), the volatility and the drawdown chart; below, XIRR and TWR over YTD, 1R, 3L and Od początku for the Total and each Account holding something (highest value today first; an inactive one only while it holds something, as in the Dashboard), or for the scope's Account alone. A fixed period reaching before History is clipped to it like the selector's. All end at History's value, so XIRR may differ from the Dashboard's while a Manual Price is set; the real return follows since L-10 (3.4.1).
- **Investment Strategies** (#76): Total has one strategy, each Account optionally its own (created and deleted in its scope); both are edited in the Strategie inwestycyjne tab, never on the Dashboard. Allocation Targets are percent of the View Scope's value per Asset Class (cash classes included, as in the sheet), each with a Tolerance Band (default ±5 pp): green within it, yellow up to twice it, red beyond; targets not summing to 100% only warn. Instrument Targets are percent of their class, among the catalog's Instruments of that class (held or not). The Planned Deposit is split by water-filling (the class furthest below its target per unit of target first, then together), normalised by the targets' sum; within a class toward its Instrument Targets (blocked with a warning unless they sum to 100%), else in proportion to the Instruments held. The deposit for full rebalancing without sales is "impossible" while a class without a target holds value. A Multi-asset Instrument with a Multi-asset Split counts in each class's value but takes no part of a class's deposit, since buying it would also add to its other classes. In Total the split names the active Accounts to buy each class on: those whose own strategy targets it, then those holding it. After a price refresh a notice names every class outside its band in Total's and each Account's strategy (no memory of the previous state). The allocation chart shows the targets beside the shares. Bands apply to class targets only. The Planned Deposit is not saved. Treemap, Account ranking, waterfall and after-tax toggle followed in #89.
- **Treemap, Account ranking, waterfall, after-tax toggle** (#89): P&L of an Account is its value less its Net Deposits, as the sheet's "Zysk / strata" ("—" while History is computed). The treemap (Total only) sizes each Account holding something by today's value and colours it green or red by its P&L against its Net Deposits, or against its value once it has taken out more than it paid in (full colour at ±30%, grey while History is computed); a click on a tile switches the View Scope. The ranking (Total only) lists the Accounts of the Account table with XIRR and TWR over the period (ending at today's value, as the Dashboard's XIRR), P&L, Net Deposits and costs; it sorts by a clicked column (again: the other way; P&L highest first by default, not remembered) and marks each column's best and worst (the highest returns and P&L, the lowest costs; Net Deposits neither). The waterfall (every scope) splits the result since the first Transaction (the unrealised and realised result, the net Dividends and interest, less the Cost Transactions; the commissions and FX Conversion Fees in the "Prowizje i koszty" tile are already inside the unrealised and realised result): Dividends and interest gross with their withholding tax under taxes, commissions and FX Conversion Fees under costs, the FX effect being the foreign cash's FX result (unless the Account excludes it) plus, for a foreign Position, how much more its cost in the Instrument's currency is worth at today's NBP Rate (or brought at a Sell's rate) than it cost at the market rate paid; the price effect is the rest. The "po podatku" toggle (not remembered) estimates 19% Belka on each Regular Account's unrealised gains at the Tax cost, offsetting the Accounts' gains and losses in Total (one PIT-38), plus each Bond Series' early-redemption fee and withheld tax (3.4.1, L-4); it shows the estimate as a tile, takes it off the unrealised result in the tiles and the Account table, off the ranking's P&L and the treemap's colour, and adds it to the waterfall's taxes. XIRR and TWR stay before tax.
- **Historia parity test**: skipped without `reference/`; compares total value, Net Deposits and value per class at each month end, tolerance 1% or 50 PLN (whichever is larger), reporting only larger differences; each explained one goes to section 9. Since L-3 the EDO Series are valued from the MF file as the sheet does, so the bond class needs no deviation.
- **Obligacje parity test** (L-3): skipped without `reference/`; each EDO row of the Obligacje tab, valued with the rates the row lists, is compared per bond with the sheet's value over the number of bonds within 0.01 PLN. The sheet does not store its valuation day, so the first-year rows give it from their linear accrual and must agree on it.

### 6.2 Stage 5 decisions (#91, #92, #93, 2026-10-16)
- **Benchmarks** (#91): a benchmark is CPI, a catalog Instrument or another Account, with an optional offset of ±x pp a year compounded daily (`(1 + x) ^ (1/365)`). Each is a daily growth factor applied to the money in it: CPI's is the GUS month-on-month index to the power of one over the month's days (a month not published adds nothing, as in the real return), an Instrument's its PLN price over the day before's (prices from History's cache, carried forward, at the NBP Rate of the day, as History converts them; split-adjusted closes as the source gives them), an Account's its daily TWR return, so its own Deposits are no growth. Every change in the View Scope's Net Deposits (as XIRR counts them, so a Transfer counts in an Account scope) goes in at the end of its day; over a period the benchmark starts at the Portfolio's value on the "from" day, as XIRR does. Before an Instrument's first price or an Account's first value the money waits as cash and the benchmark is marked "*" (shorter history), as in the sheet. The table lists the Portfolio, then each benchmark with today's value, the Portfolio's difference in PLN and percent of the benchmark, and its TWR over the period (the Portfolio's own TWR in its row); a checkbox per benchmark (remembered) shows it on the line chart of values over the period and the bar chart of today's values. The defaults are added on the first visit: CPI, LON:ACWI, LON:CSPX, AMS:V80A as in the sheet, and in place of the sheet's WSE:WIG and WSE:SWIG80TR, which Yahoo has no history of (Stooq has, but needs the user's API key), the Beta ETFs WSE:ETFBW20TR, WSE:ETFBM40TR and WSE:ETFBS80TR (WIG20TR, mWIG40TR and sWIG80TR less the funds' costs; no ETF tracks the broad WIG). Migration 0028 removes the WSE:WIG and WSE:SWIG80TR benchmarks the first defaults left on Stooq (with their Instruments, when no Transaction uses them) so the ETFs come in. Their Instruments are found in the catalog by symbol or name, else created (Yahoo symbols `ACWI.L`, `CSPX.L`, `V80A.AS`, `ETFBW20TR.WA`, `ETFBM40TR.WA`, `ETFBS80TR.WA`); after that the list is the user's (clearing the data brings the defaults back). Their history is fetched with History's from the first Transaction. No limit of five as in the sheet. In an Account scope the scope's own Account is left out. Deleting an Instrument or Account drops its benchmarks.
- **Sell Summary** (#92): a Sale Pair per Lot (part) each Sell closed, taken from the single FIFO replay (`domain/lots.py` `Replay.closed`), so DRIPs, Splits (units in the sale day's), Security Transfers and Early Redemptions (a Sell naming its Lot) count as in the Portfolio. Cost is the Lot's Actual cost, revenue the Sell's Actual Amount pro rata to the units (net of its commission, an Early Redemption's fee and withheld tax), the result their difference and the return it over the cost; days held from the Lot's date (a moved Lot keeps its purchase date). Dividends attributed: each net Dividend and DRIP of the Instrument on the Account goes per unit to the units held at the end of the day before it was paid (so a Dividend on the sale day is the pair's, one on the buy day is not); one paid with nothing held goes to the last sale's pairs when within 90 days of it and nothing was bought again in between (a narrower rule than the sheet's, bug 7); a coupon goes to the Lot it names. A moved Lot counts as held on the Account it was sold from. The tab follows the View Scope and the period (by the sale day), newest sale first; the statistics: the number of pairs, the win rate (pairs with a profit), the average days held, the result with and without Dividends, the best and the worst pair by result in PLN.
- **Passive-income calendar** (#93): a Dochód pasywny tab with the chosen year's months (not remembered, today's year first): income received (net Dividends with an Instrument and DRIPs as dividends, interest naming a Lot as bond coupons, other interest), and forecast the coupons of the Bond Series held not entered yet up to 12 months ahead (net of the Account's withheld tax, as the coupon Drafts; those already due marked "do zatwierdzenia"). Bonds paying their interest at redemption (EDO, TOS, ...) bring it with a Sell, so it is no passive income. The Monthly Income Goal (PLN, in `app_settings`) shows each month's progress (received + forecast) and the average received over the 12 whole months before this one; a stacked bar chart by source with the goal as a line. Dividends are not forecast. Follows the View Scope.

## 7. Import and verification (Q3, Q25, Q42, Q51–Q53)
- Importer framework: parse file → preview with Instrument/Account mapping (unknown tickers resolved by the user; an unknown Konto is matched to an Account or creates one through the Account dialog, prefilled with its name and PLN plus the foreign cash its rows hold, #63) → duplicate detection → commit. Duplicates: same external id skipped; otherwise similar Transaction (Account, date, Instrument, quantity, ~amount) prompts the user.
- Stage 1 importer: `reference/Newest portfolio.xlsx` (one-time). Ticker mapping from sheet formats (`EXCH:SYM`, Biznesradar, `EDO-DDMMYY` → Bond Series, `Waluty_<CUR>` → foreign cash).
- **Parity tests**: the sheet's transactions with prices/FX frozen at export date; compare Portfolio, Dashboard totals, FIFO, XIRR and bonds within 0.01 PLN; each difference explained or recorded as a deviation. Stored Historia compared at each month end for large discrepancies only (6.1). Fixtures stay in `reference/` (git-ignored).
- Stage 6: **XTB importer** (xStation account-history XLSX) and **Reconciliation** view: pair sheet vs XTB Transactions (Account, Instrument, type, quantity, date ±3 days); lists of differing pairs, sheet-only, XTB-only; per-pair or bulk "take XTB" / "keep mine"; XTB is the source of truth for XTB Accounts by default.
  - Done in L-17, as one card in Ustawienia ("Import z XTB i uzgadnianie"): the import is the Reconciliation, so an Account with nothing entered just gets XTB's Transactions as XTB-only items. Input: one export file or a folder of them, one per XTB account (its number in the file); only the "Cash Operations" sheet is read, as it has every movement with the PLN that moved (the other sheets were checked against it on the user's exports: units per ticker equal "Open Positions", cash equals its total). Times are UTC, dated by the Polish day. Only PLN XTB accounts are read (one in another currency is refused).
  - Rows: "Stock purchase"/"Stock sell" are Buys and Sells, quantity and price from the comment; an order filled in parts (one cash row per part, "15/15.3224") is one Transaction. A foreign-currency one is converted by XTB from PLN: its Actual Amount is the PLN XTB charged, at the Account's FX Conversion Fee (0% when none is set), the NBP Rate giving the Tax Amount; a PLN one takes any PLN above quantity × price as commission. "Free funds interest" is interest, its "Free funds interest tax" of the same month the tax withheld. A transfer between XTB accounts ("IKE deposit", "Transfer out/in operation") is a Cash Transfer when both accounts are imported; with one left out ("Nie importuj") it is a Deposit into, or a Withdrawal from, the one imported, as the sheet records IKE contributions. Once one leg was imported alone, importing both later adds only the other leg, so no money is counted twice. A Dividend with its withholding tax is read for a PLN Instrument only (no export with one seen yet); anything else is listed as not supported, to be entered by hand.
  - Matching: each XTB account to an Account (the one active IKE or IKZE Account is suggested for that product), each ticker to an Instrument by its Yahoo or Bossa symbol or by name ("ISAC.UK" is "ISAC"), else chosen or created through the Instrument dialog searching its Yahoo symbol; both matches are remembered (clearing the data forgets them).
  - Reconciliation: the XTB Transactions pair with those entered on the same Account within the export's range, not yet reconciled and of a type XTB's statement can show (Deposit, Withdrawal, Buy, Sell, Dividend except of a foreign Instrument, Cash Transfer), so the default cannot delete a Cost, a Split or anything else XTB does not list; by Account, type, Instrument, quantity and target Account within ±3 days, those without an Instrument also by amount within 1%; the closest date first. A Cash Transfer entered between an XTB Account and another (e.g. a bank) pairs with XTB's Deposit or Withdrawal of it and always stays. A pair agreeing on date, amount to the grosz, price, commission and tax is "zgodna". Choices, XTB's by default: a pair takes XTB's version (keeping the user's comment, its id and sheet fingerprint) or keeps the user's; an XTB-only item is added or skipped; an entered-only one is deleted or kept. Everything applies at once, all or none, blocked like any edit if a Sell would lose its cover. Resolved items are remembered (`broker_id`, `reconciled_on`, skipped XTB ids), so importing a later export offers only what is new.

### 8.1 Contribution Limits (grilling of #95, 2026-10-16)
- **What counts**: a Contribution Limit is one per Account Type (IKE, IKZE, OIPE) and calendar year, over all Accounts of that type, inactive ones too. It counts each Deposit into such an Account and each Cash Transfer into it from an Account of another type, by the Transaction's date, in PLN (the Actual Amount; the Tax Amount at the NBP Rate for a foreign-currency one). A Cash Transfer between two Accounts of the same type (moving an IKE to another institution), Withdrawals (a returned overpayment included: the bar stays over), Security Transfers and Dividends do not count. PPK, OKI and the other types have none.
- **Limits**: entered in Ustawieniach, section "Limity wpłat": a row per year, a column per type with an editable amount and that year's contributions beside it; "Dodaj rok" adds the year typed beside it (the one after the newest by default) as an empty row, a row with no limits can be removed; a limit is to the grosz. One amount per type: the self-employed enter IKZE's higher limit themselves, its 2026 value given as a hint. Only 2026 is seeded: IKE 28 260 zł, IKZE 11 304 zł (16 956 zł self-employed), OIPE 28 260 zł (MRPiPS notices of November 2025).
- **Dashboard**: a section "Limity wpłat {rok}" for the current year only, a bar per type with an active Account or a contribution this year: paid in, the limit, left and percent. Total shows every type; an Account scope shows its type's bar, the sum over all its type's Accounts ("łącznie na wszystkich kontach IKE"); a Regular Account none. A year without a limit shows "Brak limitu na {rok} — uzupełnij w Ustawieniach" instead of the bar.
- **Warning**: over the limit the bar turns red with "Przekroczono limit o X zł". Saving a counted Transaction (added, edited, imported from the sheet or applied by the XTB Reconciliation) that leaves its year over the limit with more paid than before shows one notification per type and year, never blocking the save; an edit of only the comment, or lowering an amount, does not.

## 9. Known spreadsheet bugs to fix (documented deviations)
1. Yahoo FX backup stores the whole result array instead of the rate.
2. Google Finance path never divides GBX by 100 (`toUpperCase` without `()`).
3. Missing NBP rate yields FX 0 → Total PLN 0 silently.
4. Price-fetch timeout `return` inside `forEach` does not stop the loop.
5. Biznesradar bulk takes the first 3 chars as ticker; `WSE:` prefix compared unstripped.
6. FT map STO→OSL; Yahoo suffix map missing many exchanges.
7. Sell Summary FIFO diverges from Portfolio FIFO (DRIP ignored, case-sensitive tickers, date-only sort, split-scaled fees, mixed split units for dividends, matches later buys, silent oversell truncation, over-broad post-sale dividend rule); the app's Sale Pairs come from the single FIFO engine (6.2, #92).
8. Auto currency rows include PLN commission in foreign quantity.
9. Bond ticker collisions (same type and day); sale reduces only the first matching row; unrounded costs.
10. MF rate parser rounds rates > 1 to whole percent (6.80 → 7%).
11. ROD years 11–12 have no formulas; Obligacje rate update starts at row 2 while data starts at row 3.
12. Dashboard XIRR limited to Transakcje rows 2–61.
13. History freezes XIRR/P&L/drawdown at write time; monthly summary keys months without the year.
14. Off-by-one in currency dropdown; name formula frozen; only first space removed from tickers.
15. Multi-asset existence checked on raw instead of normalised ticker.
16. Raw-value drawdown distorted by deposits (replaced by TWR-based drawdown).
17. Historia rows are written once from the state of that moment, so a Transaction entered later with an earlier date never reaches the rows already written (Net Deposits and values stay short until the day it was entered); History is recomputed from the Transactions (ADR-0002). Found by the Historia parity test (#70).
18. Bond values accrue linearly on the whole invested amount, while the MF issue letters value one bond, rounded to the grosz, and tax the profit of one bond; the app follows MF (3.4.1), so the sheet's bond values differ by grosze.
19. A TOS keeps accruing its third year's rate after its maturity, and a TOS bought on 29 February counts its years to 1 March; the app holds a matured bond at its maturity value and dates its years by the last day of a shorter month (3.4.1). Found by the bond parity test (L-11).
