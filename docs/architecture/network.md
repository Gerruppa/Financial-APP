# HTTPS trust and network errors (#309)

`app.py` `main` calls `truststore.inject_into_ssl()` first, so every `urllib` download (price sources, bond data, NBP rates, app updates) verifies certificates through Windows CryptoAPI. Python alone trusts only the roots already in the Windows store, which Windows fills lazily (a root appears once a CryptoAPI client, not Chrome or Edge, has needed it); on a fresh computer gov.pl and stat.gov.pl (Certum Trusted Root CA) failed while static.nbp.pl (cross-signed to the older Certum Trusted Network CA) worked. CryptoAPI fetches a missing root through Windows Update.

`sources/network.py` `network_hint(error)` is the advice after a failed download without an HTTP status: `CERTIFICATE_HINT` for an `ssl.SSLCertVerificationError` (raised directly or as a `URLError` reason; a wrong clock or an antivirus scanning HTTPS remain the usual causes), otherwise `CONNECTION_HINT` ("Sprawdź połączenie z internetem."). Yahoo, Stooq, Bossa, bankier.pl, analizy.pl, gpwcatalyst.pl, NBP, the bond data sources and the app update check (`sources/app_update.py`) end their messages with it; `fund_profile.py` swallows its failures and says nothing. Tests: `tests/test_network.py` (the price, search and update sources), `tests/test_nbp_rates.py`, `tests/test_bond_data.py`, `tests/test_startup.py`.
