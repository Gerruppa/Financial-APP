# Export

`domain/export.py` builds the Transakcje rows for export (every type, the commission with its "Waluta prowizji" (#124), the Actual and Tax Amounts, origin, comment); `sources/export.py` writes them to CSV (UTF-8 with BOM, `;`, decimal comma, day-first dates) or XLSX. The Transakcje tab's "Eksportuj CSV" and "Eksportuj XLSX" buttons hand the file to the browser.

## Reports (#240, #241, parent #239)

`domain/report.py` is the report model: `Report` (name, title, `Section`s of typed rows, notes), `Percent` (a fraction shown as percent), `sale_summary_report` (the year's Sale Pairs from `sale_pairs` and `in_view`, with `sale_stats`) and `results_report` (`period_results` over the year and `results_rows` for the Total and each Account, from History's days passed in), `last_finished_year`; an empty year gives no sections and the note `NOTHING_TO_REPORT`. `sources/report_export.py` `report_to_xlsx` writes a sheet per section (numbers, `Percent` as `0.00%`, real dates `DD.MM.YYYY`, formula-like text kept as text) and `export_sale_summary` / `export_results` return the file name (`<report>-<year>[-<Account>].xlsx`, `safe_file_part` from `sources/export.py`) and bytes. `ui/report_export.py` `export_controls` is the year select (`<key>-export-year`, default the last finished year) and button (`<key>-export`) on the Sell Summary (`sale`) and Wyniki (`results`) tabs; Wyniki asks to wait while History is still computing. The domain imports no openpyxl; later report tickets add reports to the same model and renderer.

Portfolio and passive income (#241): `domain/report.py` `portfolio_report` takes a `PortfolioSnapshot` (positions, cash, PLN prices and NBP rates ready-made, Term Deposit interest accrued) and gives the sections Pozycje (price, value, result per Position; a Position with no price that day has no value and the note `BRAK_WYCENY`) and Konta (`account_value` per Account, as the tab shows it); `passive_income_report` takes the `IncomeItem`s ready-made and lists the received ones of the year in the View Scope (Podsumowanie by kind, Wpływy by day; forecasts left out). `sources/report_export.py` `export_portfolio` builds the snapshot: for the current year from `todays_view` (so it agrees with the Portfolio tab), for a past year from `history_inputs` replayed to 31 December through `open_positions` and valued by `prices_on` and `rates_on` (`domain/portfolio_history.py`, the History pricing, cached prices only); `export_passive_income` fetches `income_items`. The Portfolio (`portfolio-export*`) and Dochód pasywny (`income-export*`) tabs use the same `export_controls`.

Annual PDF report (#242): `sources/pdf_report.py` `annual_report_to_pdf(scope, year, generated, reports)` lays the reports out with reportlab (Platypus), A4 portrait: a title page (the scope, the year, the date generated), then a heading per report (Wyniki roku, Portfolio na koniec roku, Sprzedaże (FIFO), Dochód pasywny) with each `Section` as a table (`repeatRows=1`, so a long table continues on the next page under its header; no charts), the one-line `DISCLAIMER` and the page number in every footer. Cells are formatted with `domain/formatting.py` as on screen (a `Liczba` column as a quantity). The text is set in DejaVu Sans (`ui/assets/fonts`, with its licence), registered once, because the PDF base fonts lack the Polish letters; `packaging/kapita.spec` copies the folder with the other assets. `sources/report_export.py` `export_annual_pdf` builds the same four reports as the XLSX exports (the `_results`, `_portfolio`, `_sale_summary` and `_passive_income` builders those exports share), so the figures agree, and names the file `raport-roczny-<year>[-<Account>].pdf`. The Wyniki tab's `export_controls` has a second button (`results-pdf`, "Raport roczny PDF") beside the XLSX one, using the same year select; like the XLSX it waits for History. `pypdf` (dev) reads the PDF back in the tests: page counts and the text, no pixel comparison.
