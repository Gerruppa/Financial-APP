# Browser and demo mode, screenshots

For looking at the UI from outside the native window, mainly so an agent can check a visual change. `app.py` `parse_args` reads the start options (`allow_abbrev=False` and `parse_known_args`, since the startup tests run `main.py` under pytest's own `sys.argv`): `--browser` serves the UI on `localhost:--port` (default 8080) without pywebview and opens no tab (`window_size` alone would switch NiceGUI to native mode, so it is left out); `--demo` implies `--browser`, and `start_demo_database()` first points `FINANCIAL_APP_DATA_DIR` at `demo_dir()` (`%TEMP%\KAPITA-demo`), deletes its database and fills a fresh one through `sources/demo_data.py` `seed_demo_data(engine, today)`: two PLN Accounts (Konto maklerskie, IKE) and four made-up `DEMO …` Instruments with Manual Prices only, with ten Transactions over the year before `today` (deposits, buys, a sell, a dividend) and a Total Investment Strategy whose classes fall in each band colour. The demo skips the refresh at start, so it needs no network; History-based figures (Wpłaty netto, XIRR) show "—" until History is computed. The real data folder is never touched.

`scripts/screenshot.py <tab> … --out <dir>` starts `main.py --demo` on a free port, shoots each tab (its route without the slash, `dashboard` for `/`) with headless Chrome or Edge into `<dir>/<tab>.png` and stops the app; `--theme golden` saves that Theme in the demo database first. The project skill `.claude/skills/kapita-screenshot` tells an agent when and how to use it. Tests: `tests/test_demo_data.py`.
