# Undo bar

Deleting a Transaction asks no "are you sure?": the transaction dialog's `delete-transaction` deletes at once (`sources/transaction_saving.py` `delete_saved`, so a Sell left uncovered still shows its error in the dialog) and `ui/undo.py` `offer_undo(message, undo)` shows a bar at the foot of the window, `undo-bar`, with "Usunięto transakcję." and the button `undo-button` ("Cofnij"), for `UNDO_SECONDS` (8; a module value a test shortens). The bar is built in the page's layout, not in the dialog, so it outlasts the closing dialog; a newer bar replaces an older one still showing, and `ui.timer` removes it. Clicking "Cofnij" runs `restore_saved` (`persistence/transactions.py` `restore_transaction`: the Transaction back under its own id, refused with a Polish message when another took the id or a Sell would be left uncovered, which the bar then shows as a notification), warns like any save ("Przywrócono ...") and publishes `Change.TRANSACTIONS` through the dialog's `on_saved`.

`.k-undo` in `ui/theme.py` is an inverted pill (`--k-text` on `--k-page`), so it reads in both Themes; its button takes no Quasar colour (the primary would not read on it). `offer_undo` is `action_bar(kind, message, label, action, seconds)` (pill `k-<kind>`, markers `<kind>-bar` and `<kind>-button`), which also shows the negative cash warning's `covering-bar` (`.k-covering`, see `transaction-saving.md`) above it, so a delete that leaves cash negative shows both; a newer bar replaces an older one of its kind only. A bar whose time is up while a dialog of class `HOLDS_BARS` (`k-holds-bars`: the covering Deposits window) is open stays, checking every `HOLD_CHECK_SECONDS` (1), and gets its full time afresh once the window closes, so "Cofnij" can undo a delete the window has just covered. Other deletes (Account, Instrument, Recurring Rule, Term Deposit, ...) still ask: restoring them needs more than one row. Tests: `tests/test_transaction_edit_ui.py`, `tests/test_transactions_repository.py`.

Undoing after a change (#267): `delete_saved`'s value is all the Transactions it left, and "Cofnij" runs `ui/restore_dialog.py` `undo_delete`, which compares them with what is saved by then (`sources/transaction_saving.py` `since_deleted`, `domain/save_warnings.py` `since_delete` → `SinceDelete`, on the deleted Transaction's Accounts and target only). Nothing changed: it restores at once, as before. Otherwise the window `undo-window` ("Cofnąć usunięcie?", `restore_dialog`) says what comes back ("Przywrócę: ...", in `ui/xtb_import.py` `Describer` words) and explains each difference: the covering Deposits saved since (`COVERING_COMMENT` Deposits, e.g. from the negative cash warning the delete raised), which made up for its cash, so keeping them leaves the cash their sum higher than before the delete; the Transaction that took its id (SQLite hands a freed last id to the next row): a covering Deposit can go with the undo, any other blocks it ("wpisz ją ponownie przyciskiem +"); and each other Transaction added, changed (then → now) or removed there, which stays, the restore's own warnings showing what no longer adds up. Buttons: `undo-drop-covering` ("Przywróć i usuń wpłaty uzupełniające", only with covering Deposits and the id free once they go) runs `restore_saved(engine, transaction, dropping=<their ids>)` (`restore_transaction` deletes them first in the same session, all or none), `undo-restore` ("Przywróć bez zmian", off while another holds the id), `undo-cancel`. The module is apart from `ui/undo.py`, which `ui/save_warnings.py` imports, as `Describer`'s module imports that. Tests: `tests/test_covering_deposits_ui.py`, `tests/test_transaction_saving.py`, `tests/test_save_warnings_domain.py`.
