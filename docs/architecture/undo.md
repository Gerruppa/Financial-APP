# Undo bar

Deleting a Transaction asks no "are you sure?": the transaction dialog's `delete-transaction` deletes at once (`sources/transaction_saving.py` `delete_saved`, so a Sell left uncovered still shows its error in the dialog) and `ui/undo.py` `offer_undo(message, undo)` shows a bar at the foot of the window, `undo-bar`, with "Usunięto transakcję." and the button `undo-button` ("Cofnij"), for `UNDO_SECONDS` (8; a module value a test shortens). The bar is built in the page's layout, not in the dialog, so it outlasts the closing dialog; a newer bar replaces an older one still showing, and `ui.timer` removes it. Clicking "Cofnij" runs `restore_saved` (`persistence/transactions.py` `restore_transaction`: the Transaction back under its own id, refused with a Polish message when another took the id or a Sell would be left uncovered, which the bar then shows as a notification), warns like any save ("Przywrócono ...") and publishes `Change.TRANSACTIONS` through the dialog's `on_saved`.

`.k-undo` in `ui/theme.py` is an inverted pill (`--k-text` on `--k-page`), so it reads in both Themes; its button takes no Quasar colour (the primary would not read on it). `offer_undo` is `action_bar(kind, message, label, action, seconds)` (pill `k-<kind>`, markers `<kind>-bar` and `<kind>-button`), which also shows the negative cash warning's `covering-bar` (`.k-covering`, see `transaction-saving.md`) above it, so a delete that leaves cash negative shows both; a newer bar replaces an older one of its kind only. Other deletes (Account, Instrument, Recurring Rule, Term Deposit, ...) still ask: restoring them needs more than one row. Tests: `tests/test_transaction_edit_ui.py`, `tests/test_transactions_repository.py`.
