# First-run window (#270, #288)

`ui/first_run.py` `FirstRunWizard(engine, open_settings, add_transaction)` is a five-step window on the shared `ui/wizard.py` (prefix `first-run`): Witaj w KAPITA (what the app does, that the data stays on this computer), Konta (the Account Types, their taxes and the IKE/IKZE/OIPE Contribution Limits; the Accounts so far in `first-run-accounts` and `first-run-add-account`, which opens `ui/accounts.py` `open_account_dialog` and redraws the step), Historia transakcji (`first-run-import` goes to Ustawienia > Import with the XTB and crypto imports, `first-run-add-transaction` opens the Transaction form), Wyceny (the Price Sources by kind, no key needed; `first-run-instruments` goes to Ustawienia > Instrumenty) and Gotowe (where the tabs are, and how to reopen it, `first-run-done`). Only the Konta step saves data; the others close the window and go to the screen that does the job. A Transaction saved from the form `first-run-add-transaction` opened (`add_transaction(then)`, `_transaction_saved`) opens the window again.

Which steps are done comes from the data, never stored, so it holds for an old database too: Konta while there is an Account, Historia transakcji while there is a Transaction, Wyceny while there is a Transaction and `sources/prices.py` `unpriced_instruments` (the "Instrumenty bez wyceny" list) holds only Instruments with a Manual Price, as those have a price. The three are those steps' `WizardStep.done`, so the window lists its steps with a tick (see `wizard.md`), and `progress()` counts them. `open` goes to the first step not done, or Witaj while none is or once all are.

The header's chip `first-run-chip` (`chip`, drawn only with `offer_first_run`) says "Pierwsze kroki n/3" while a step is not done; `first-run-chip-open` opens the window and its × `first-run-chip-hide` saves `FIRST_RUN_CHIP_HIDDEN` (`ui.first_run_chip_hidden`, kept on clearing the data), so it never shows again. The shell redraws it on `Change.TRANSACTIONS`, `PRICES` and `INSTRUMENTS` and through `on_progress`, which the window calls after an Account is added in it and Ustawienia > Konta after an Account is saved or deleted there (`progress_changed`). The Stooq key is not offered: its section (`ui/price_sources.py`) is not in Ustawienia, as History runs on Yahoo.

`build_shell(offer_first_run=True)` (passed by `app.py`; tests leave it off, so their empty databases open no window) calls `open_if_new`: the window opens while `list_accounts` is empty and `persistence/settings.py` `FIRST_RUN_DISMISSED` (`ui.first_run_dismissed`, kept on clearing the data) is unset. However the window closes (Zamknij, a step's button, Esc), its `on_value_change` saves the key, so it never opens by itself again; the chip and the button below reopen it either way. Ustawienia > Konta's `first-run-open` ("Pierwsze kroki", `AccountsSection(open_first_run=)`) reopens it at any time. Each Ustawienia page drawn sets `on_accounts_changed` to its `AccountsSection.changed`, so an Account added in the window shows in Konta (and redraws the chip) whichever button opened it. The window is made in `ui.context.client.content`, so it outlives the tab it opened on.

Going to a section: `ui/settings.py` `SettingsSection` (one per shell, `build_settings_page(section=)`) holds the section the next Ustawienia page starts on (`key`, consumed when drawn) and the page's `ui.tabs`; `show(key)` switches the tabs of the page on screen, or keeps the key for the page `ui.navigate.to` draws next. Tests: `tests/test_first_run_ui.py`.
