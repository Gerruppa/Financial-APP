# Multi-asset (#75, spec 6.1)

`InstrumentDraft.multi_asset_split` (percent by Asset Class id, summing to 100, zero shares dropped; table `multi_asset_shares`, migration 0019, saved with the Instrument or alone by `persistence/instruments.py` `set_multi_asset_split`; a class in a split cannot be deleted). `Instrument.class_parts(value)` spreads a value by the split's class names (`split_class_names`, the last part taking the remainder) or keeps it whole in its class; `daily_history` and `dashboard` use it, so History, the allocation and the class-share chart count it. `is_multi_asset` is the marked Multi-asset class (`AssetClass.multi_asset`, column `asset_classes.multi_asset`, migration 0020, set on the seeded `MULTI_ASSET_CLASS` and kept through a rename; `Instrument.in_multi_asset_class`) or a split; `Position.value_or_cost` values a Position at its price or cost. `domain/multi_asset.py` `multi_asset_holdings` feeds `ui/multi_asset.py` `MultiAssetPage` (the Multi-asset tab, rows `multi-asset-row-<id>` opening `open_split_dialog`, sums `multi-asset-class`); `split_editor` (fields `split-share-<class id>`, `split-total`) sits in the Instrument dialog while the class is Multi-asset, and `ui/transactions.py` opens the split dialog after a new or edited Buy or DRIP of a Multi-asset Instrument without one; any other save (the sheet import, the XTB Reconciliation, a bond Draft) names those it bought without a split (`domain/save_warnings.py` `SaveWarnings.unsplit`). `domain/instruments.py` `parse_optional_number` reads the Instrument dialog's and the split's number fields. A split saved in Ustawienia or the tab invalidates History (`build_settings_page(..., on_instruments_changed)`).
