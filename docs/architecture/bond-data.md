# Bond data (Stage 3, L-1, spec 3.4.1)

`domain/bonds.py` (`BondType`, `TERM_MONTHS`, `SeriesTerms` with the rate and interest of each period as MF lists them, `CpiReading` year-on-year and month-on-month GUS indices, `ReferenceRate`, `BondDataError`; rates are fractions). `sources/bond_data.py`: `MfBondFile` (the gov.pl page's "Dane dotyczące obligacji detalicznych" .xls read with xlrd, `parse_mf_file`, a sheet per type, one or two header rows), `GusCpi` (the stat.gov.pl CSV, cp1250, `parse_gus_csv`) and `NbpReferenceRates` (the NBP archive XML, `parse_nbp_rates`), each with an injectable `fetch`; `refresh_bond_data(engine, BondDataSources, now)` fetches each source not fetched successfully today and replaces its copy (`persistence/bond_data.py`, tables `mf_bond_series`, `cpi`, `nbp_reference_rates`, `bond_data_status`, migration 0022), a failure keeping the last copy. The shell runs it after the price refresh (`_refresh`) and at start-up when only it is due; `build_shell(..., bond_data=...)` takes test sources and defaults to none when test `sources` are given. `ui/bond_data.py` shows red "Dane obligacji: n błędów" (`bond-data-status`) with the reasons. Tests run on `tests/fixtures/mf/` (the whole MF file), `gus/` and `nbp_reference/`.
