# `ui/changes.py` (#112)

The window's change events. `Change` names what changed (Transactions, prices, bond data, View Scope, History, Instruments, Recurring Rules, the layout, Term Deposits); `ChangeEvents.subscribe(redraw, changes)` and `publish(*changes)` redraw each subscriber of a published change once, in subscription order, a change published by a subscriber joining the running publish. Each tab class (and `UnpricedSection`, `ScopeSwitcher`) declares `CHANGES`, the changes it redraws on (the `Redrawing` protocol); `build_shell` subscribes them and the header's draft and bond data states, and only publishes: after a save, a price refresh (prices and bond data), a bond data refresh, a scope switch, an Instrument change and once History is outdated or computed. History's invalidation is subscribed first, to Transactions, prices, bond data and Instruments, so it runs before any tab redraws (#114: a bond data refresh outdates History and redraws Portfolio, Multi-asset, Strategie and, through History, the Dashboard).
