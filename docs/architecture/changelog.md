# Changelog (#200, spec 2)

`domain/changelog.py` `parse_changelog(text)` reads the changelog's Markdown into a `Changelog`: its `unreleased` `Group`s (`## Nieopublikowane`, on top) and its `releases` (`Release`s), newest first (`## 1.1.0 — 2026-11-02`, an optional summary paragraph, then up to three `Group`s, `### Nowe funkcje`, `### Poprawki` and `### Zmiany` in that order, of `- ` entries); `Changelog.release(version)` finds one. A text not starting with `# Historia zmian`, a malformed heading or date, an unknown or misordered group, an empty group or version, a line in a group that is no entry, a second or lower "Nieopublikowane" or versions out of order raise `ChangelogError` (Polish). `is_newer(version, than)` compares numerically (`version_key`); `to_announce(last_seen, current)` is true only when `current` is newer than the last version seen, so a new User or the first start after this change only records it.

The text is `ui/changelog.md`, shipped as package data like `faq.md` and kept by hand (the rule is in `CLAUDE.md`); `tests/test_changelog_ui.py` fails while it has no section for `financial_app.__version__`. `ui/changelog.py`: `version_label(version)` is the version under the logo in `ui/shell.py` (`app-version`, pointer cursor, tooltip "Historia zmian"), which opens `open_changelog(title, releases)` (`changelog`, a scrolling dialog) with every released version; `announce_new_version(engine, version)`, called as the shell builds, records a version newer than the one in the setting `ui.last_seen_version` (`LAST_SEEN_VERSION`, kept on clearing the data; going back to an older version records nothing, so the newer one is not announced twice) and, after an older one, opens the dialog as "Co nowego" with only that version. "Nieopublikowane" is never shown. A `ChangelogError` never stops the start; clicking the version then notifies it.
