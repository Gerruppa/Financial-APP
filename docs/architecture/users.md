# Users, login and switching (#195, spec 2.1, ADR-0010)

`domain/users.py`: the rules for a pseudonym (`pseudonym_error`: required, unique regardless of case) and a password (`password_error`: at least `MIN_PASSWORD_LENGTH` = 4 characters, repeated alike), the Polish messages, and the scrypt hash (`hash_password` gives `scrypt$N$r$p$salt$hash` with a random salt, `verify_password` compares in constant time and treats a malformed hash as a mismatch).

`persistence/users.py` `UserStore(root)`: the list of Users is `users.json` in the app-data folder (`paths.USERS_FILE`; `{"users": [{id, pseudonym, password_hash}]}`, saved aside and renamed over). Each User's folder is `<root>/<id>` (a random hex id that never changes, so renaming a User later moves nothing) with `financial_app.sqlite3`, `backups/` and `financial_app.log`. `create` validates, makes the folder and, when the list was empty, moves the database (with its WAL and journal files), the log and `backups/` from the app-data folder into it, so the first start of this version loses nothing. `sign_in` answers a wrong password with `UserError("Nieprawidłowe hasło")`, with no limit on attempts. A User whose `password_hash` was removed by hand (the reset the login screen describes) has `password_hash=None`: the login screen says so and the next password typed is set with `set_password`. The password is a lock, not encryption.

`ui/login.py` `build_login(store, on_signed_in)`: the screen is always drawn in the default Theme (`apply_theme(Theme.LIGHT)`), since the list holds no Theme. Markers: `login`, `login-user` (the pseudonyms), `login-password`, `login-submit`, `login-error`, `login-hint`, `login-new`, `login-forgotten` (a dialog `forgotten-password` naming `users.json` and the line to remove), `new-user-pseudonym`, `new-user-password`, `new-user-repeated`, `new-user-submit`, `new-user-error`, and `password-is-a-lock` (the note that the password does not encrypt). With no Users it opens straight on creating one.

Switching: Ustawienia has a "Użytkownik" card (`user-section`) with `switch-user` ("Przełącz użytkownika"), shown only when `build_shell` gets `on_switch_user` (not in `--demo`). `app.py` `Session.close` calls `ui/shell.py` `stop_background_work(engine)`, which cancels the shared refresh and History of that engine (`ui/history.py` `forget_history`) and disposes the engine, then the window goes to `/`, where `root` draws the login screen. A request already on the network finishes in its worker thread, and its result is dropped. The header avatar's menu, the "Użytkownik" settings section (change pseudonym and password, delete) and the Theme move are #177 and #196.

Tests: `tests/test_users_domain.py`, `tests/test_users_store.py`, `tests/test_startup.py` (the whole flow through `main.py`). Tests of the shell itself call `build_shell(engine)` and never meet the login screen.
